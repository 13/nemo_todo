# nemo app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Flutter app for Android and Web: fully usable offline from first launch, with lists, tasks, subtasks, due dates and reminders, tags and priority, search, then optional account + sync against the nemo server with live updates.

**Architecture:** Local-first. Every screen watches drift streams from `AppDatabase`; every mutation goes through a repository that stamps an HLC, writes the row and an outbox entry in one transaction. `SyncEngine` watches the outbox, pushes and pulls, and applies remote rows with the same `incomingWins` rule. Riverpod 3 (`@riverpod` notifiers over manual repository providers), go_router with a `ShellRoute`, Material 3 with a `NemoColors` extension, `L.of(context)` for strings.

**Tech Stack:** Flutter 3.47.2, flutter_riverpod 3.4 + riverpod_annotation/generator, go_router 18, drift 2.34 + drift_flutter 0.3, freezed 4, dio 5.11, flutter_secure_storage 11, flutter_local_notifications 22, connectivity_plus 6, mocktail 1.

**Spec:** `docs/superpowers/specs/2026-09-07-nemo-design.md`

## Global Constraints

- Workspace member; `flutter analyze` clean under `very_good_analysis` + `riverpod_lint`; `dart format` applied; generated files committed.
- Never import `package:drift/native.dart` from `lib/` (breaks the web build); tests construct `AppDatabase(NativeDatabase.memory())`.
- All user-visible strings through `L.of(context)`; catalogues `app_en.arb` (template), `app_de.arb`, `app_it.arb` with identical key sets.
- Colours only through `Theme.of(context).colorScheme` or `context.nemoColors`; never raw hex in widgets.
- Times: `dueAt` is UTC epoch ms; `dueHasTime` false means "that calendar day" (stored as local midnight of that day converted to UTC ms).
- Coverage floor 80 % (`dart run ../tool/check_coverage.dart 80` from `app/`).
- Android: `applicationId dev.ben.nemo`, `minSdk 26`; permissions `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, `SCHEDULE_EXACT_ALARM` not requested (inexact reminders).

### Task 1: Database, KV store and sync writes

**Interfaces:**
```dart
class AppDatabase extends _$AppDatabase { AppDatabase(super.e); factory AppDatabase.open(); int get schemaVersion => 1; }
class KvStore { KvStore(AppDatabase db); Future<String?> get(String key); Future<void> set(String key, String? value); Stream<String?> watch(String key); }
abstract final class KvKeys { nodeId, hlcLast, cursor, themeMode, serverUrl, username, lastSyncAt, discardedNotice }
extension SyncWrites on AppDatabase {
  Future<void> upsertList(TaskList row, {required Hlc stamp});      // row.updatedAt must equal stamp; writes outbox + kv hlcLast
  Future<void> upsertTask(Task row, {required Hlc stamp});
  Future<void> upsertSubtask(Subtask row, {required Hlc stamp});
  Future<Task?> applyRemote(SyncChange change);   // merge; returns the task written (for reminder rescheduling) or null
  Future<void> enqueueAll();                       // every row → outbox (sign-in)
  Future<List<SyncChange>> outboxChanges();        // rows as they are now
  Future<void> ackOutbox(Iterable<SyncChange> pushed); // delete entries whose updatedAt is unchanged
  Stream<int> watchOutboxCount();
}
```
- Tests (`test/core/db/sync_writes_test.dart`): upsert writes row + outbox + hlcLast; second upsert keeps one outbox row; applyRemote keeps newer local; applyRemote revoke deletes; ackOutbox skips rows edited after the push; enqueueAll counts every row.
- Commit `feat(app): local database with outbox`.

### Task 6: Auth, sync client, engine, SSE, settings wiring

**Interfaces:**
```dart
class AuthState { String? serverUrl; String? username; bool get connected; }   // token lives in secure storage
class AuthController (keepAlive Notifier<AuthState>) { Future<void> signIn({url, username, password}); Future<void> signUp({...}); Future<void> signOut(); }
class SyncClient { SyncClient(Dio dio, {required String baseUrl, required String token}); Future<SyncResponse> sync(SyncRequest); Future<List<ListMember>> members(listId); Future<void> share(listId, username); Future<void> unshare(listId, username); static Future<({String token, String username})> login/signup(Dio, url, username, password); }
class SyncState { SyncStatus status (idle|syncing|offline|error|signedOut); DateTime? lastSyncAt; int pending; String? error; int discarded; }
class SyncEngine (keepAlive Notifier<SyncState>) { Future<void> syncNow(); void requestSync(); Future<void> onSignedIn(); Future<void> onSignedOut(); }
class SseClient { SseClient(Dio, {baseUrl, token, onChanged}); void start(); void stop(); }
```
- Engine: single in-flight run with rerun flag; loop while `hasMore`; ack outbox; apply changes via `applyRemote`; write `list_meta` from `members`; persist cursor and `lastSyncAt`; feed `serverHlc` into the clock; 2 s debounce on outbox count; connectivity + resume triggers; 401 → signed-out state.
- Screens: `AccountScreen` (server URL, username, password, sign in / create account, errors), settings tiles (account, sync status + "Sync now", sign out), `MembersScreen` (owner: add by username; remove), shared badge on list cards from `list_meta`.
- Tests: engine against a mocked `SyncClient` (push clears outbox, rejected reverts and counts, hasMore loop, 401), SSE frame parser, auth controller storage, account screen validation.
- Commit `feat(app): accounts and sync`.
